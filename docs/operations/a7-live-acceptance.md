# A7 实盘验收

2026 年国庆后 **10 月 8 日**开市。设计初稿里的 10/9 已更正，依据[上交所公告](https://www.sse.com.cn/disclosure/announcement/general/c/c_20260915_10832273.shtml)。项目交易日历原本就正确识别 10/8。

## 单位约定

- `QuoteSnapshot.volume` 和内存 `DailyBar.volume` 都是股。
- `quote_bars_daily.volume` 保留兼容的手列。新增可空 `volume_shares` 保存源提供的精确股数；读缓存优先用它，旧行为空时才把手乘 100。正常服务初始化只添加列，不重写旧数据；只读取证命令不迁移。
- AKShare 东财日 K 的主板、创业板、科创板成交量都是手，依据 [AKShare 官方文档](https://akshare.akfamily.xyz/data/stock/stock.html)。腾讯日 K 的主板、创业板是手，688 科创板是股；分别用 600519、300750、688525 原始响应核对并做回归测试。不能把不同源的单位混用。北交所等尚未核对单位的市场不启用腾讯日 K 回退。
- 告警的 `volume_avg5d`、`volume_avg20d` 使用快照日期之前的完整 5/20 根缓存日 K，单位为股。不足窗口或最新日期不是上一交易日时保持 0；显式调用参数优先。
- `volume_ratio` 优先使用腾讯直接给出的量比。旧源无此字段时的累计成交量/5 日日均量只是兼容回退，不等同于通常按交易时间调整的量比。

日 K 暖缓存只请求和保存上一交易日及更早的数据，显式排除接口意外返回的当天/未来行。东财失败或缺少所需日期时回退腾讯 `newfqkline/get` 的前复权 `qfqday`，金额万元换元，精确股数落库。启动后每小时后台检查一次，不阻塞个股轮询；每个进程对每个已完成交易日至少重新取数一次，以修复旧版本可能留下的半日 K。已校验且数量足够的缓存不重复请求。两源都失败时，这只股票的历史暂不可用，等待下次刷新恢复。

## 行情来源选择

Compose 明确默认 `MARKET_SCAN_FEED=tencent`、`SECTOR_FEED=tencent`；设为 `eastmoney` 可选择旧源，不能把另一源当作静默回退。消息和取证 JSON 显示实际来源及提供方总数。

- 市场使用[腾讯官网](https://stockapp.finance.qq.com/mstats/)同款 `getBoardRankList`：`aStock`、涨幅降序/升序、量比降序，各 100 条，共 3 个请求。当前上游总数 5,573，包含沪深京；没有证明它与旧东财筛选的 5,922 个代码集合完全相同。
- 行业使用腾讯 `getRank`、`hy2` 的 **申万二级行业**，100 条一页，当前 124 个行业，共 2 页。它与旧东财多级行业集合不同，不自动映射名称。行业规则需用当前返回的行业名；未匹配的规则会记录 `sector_rule_unmatched`，不能视为已恢复该规则。
- 东财公开参数、官网游客入口、传输和 DNS 对照仍未恢复连接。现有证据不能确定是封 IP 或 DNS 故障；保留原异常，不改变 TLS 校验，不接未经验证的延迟源。

## 只读取证

此前 `75562ec` 已包含 `quote_watcher.tools.verify_feeds`；本轮修复需要部署新增 provider 和精确股数字段的镜像。

在服务器项目目录、交易时段执行一次，使用唯一文件名保留原始证据：

```bash
mkdir -p data/acceptance
docker compose exec -T quote_watcher python -m quote_watcher.tools.verify_feeds \
  --db /app/data/quotes.db > data/acceptance/a7-20261012-1000.json
```

本地也可执行 `uv run python -m quote_watcher.tools.verify_feeds --db data/quotes.db`。本地网络结果只说明本地状况，不能代替阿里云出口测试。

命令只请求腾讯的 600519、300750、688525 和环境中选择的市场/行业接口；SQLite 使用 `mode=ro`、`query_only`，兼容有/无精确股数字段的数据库，可读取已提交 WAL，不创建数据库、不暖缓存、不运行迁移、不发送告警，也不调用模型。每路总等待上限 45 秒，个股腾讯请求不重试。直接在本机运行时需明确设置相同的两个 provider 环境变量，不能用本机成功代替服务器出口验证。

JSON 包含采集时间、市场时段、三路返回数量/异常类型、快照时间及股数、已完成日 K 数量和 5/20 日均量。错误只记录异常类别，不把完整请求或凭据写入证据。

退出码 0 表示具备人工对比的基础条件；退出码 2 表示条件不齐，JSON 仍会输出。`acceptance_status` 始终为 `pending_manual_comparison`，没有自动验收通过。以下任意情况都会阻止具备对比条件：

- 非交易时段；
- 任意一路失败或空结果；
- 三只代表股票缺失，或快照早于采集时间超过 90 秒/晚于采集时间超过 5 秒；
- 源量比缺失；
- 日 K 不足 20 根，或最新已完成日 K 不是上一个交易日。

例如 10/8 盘中，最新已完成日 K 应为 9/30；10/9 盘中应为 10/8。当天和未来的缓存行不参与均量。历史不足时先检查正常服务的日 K 暖缓存日志，取证命令不会补数据。

## 人工确认与记录

在记录的时间点，用独立行情软件逐只核对价格、累计成交量（先统一为股）、5/20 日日均量和源量比，保存软件名称、截图或导出的原值及时间。考虑两次采样间成交变化；出现约 100 倍差异时先检查单位，不能通过放宽容差直接验收。

排名和行业接口没有响应时间戳，非空结果不证明实时性。还需按消息显示的提供方集合和申万二级行业口径，核对涨/跌/量比排名和行业涨跌与独立行情一致。

再只读查看 `quote_feed_ok` 日志和第一条实际触发告警，确认数据时间、成交量标识和规则值。不要伪造触发发送测试消息。逐条记录结果、差异原因、证据文件及审核人；有缺项时 A7-4 仍为待验收。

本命令不替代 B0 的人工标注/模型验收，也不替代持续运行观察。SSH 已恢复可用，部署后的运行证据另存于私有部署目录。
